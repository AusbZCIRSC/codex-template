# spark-tutor

A RAG-based AI chat system for training and education centers.

spark-tutor helps learners, teachers, and training staff interact with course-specific knowledge through an AI assistant. The system currently supports four core learning workflows:

1. Socratic tutoring
2. Teacher-support questions
3. Exercise generation and solution verification
4. Direct teaching of a topic

More workflows may be added later.

## Current status

This project is in development and test phase.

During development, users may run the application locally with all required services. In production, the system is intended to be hosted centrally on servers.

## Core architecture

spark-tutor consists of:

- React + Vite frontend
- Python FastAPI backend
- Separate embedder service
- Separate retriever service
- PostgreSQL database with vector extension
- Docker Model Runner for chat LLM and embedding LLM
- Docker Compose for local orchestration

## Deployment model

### Development and test phase

Users receive a local installation containing:

- Web UI
- Retriever backend
- PostgreSQL database
- Chat LLM
- Embedding model if needed
- Docker Compose setup

### Production phase

The system will be hosted centrally.

Production users should only interact with the web UI. Admin-only services such as embedding and ingestion must not be exposed to normal users.

## Main workflow

When a user sends a prompt:

1. The system reads the user prompt and relevant chat history.
2. The chat LLM classifies the request into one or more supported learning workflows.
3. The system builds a workflow-specific prompt.
4. The retriever fetches class/training-specific knowledge.
5. The chat LLM generates the final response.
6. The chat and messages are persisted.

## Authentication

The first version uses simple authentication:

- Login
- Logout
- Password change
- No self-service sign-up

Later versions may replace this with single sign-on.

## User and class model

Each user belongs to one specific training/class.

The class is represented by a unique ID. RAG content must be filtered by tags matching the user’s training/class ID.

## File attachments

Users may attach files to prompts.

Attachments are especially important for:

- Checking exercise solutions
- Reviewing user-submitted work
- Generating feedback from documents
- Using external exercises not generated by spark-tutor

## User settings

User-specific assistant behavior settings must be persisted.

Examples:

- Preferred teaching style
- Level of detail
- Degree of Socratic guidance
- Personalization preferences

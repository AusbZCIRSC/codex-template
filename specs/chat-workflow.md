# Feature: Chat AI Workflow

## Status

Draft

## Problem

Users need one chat interface that can support different learning behaviors.

The system must decide which learning workflow is needed before generating the final assistant response.

## Workflows

Initial supported workflows:

1. Socratic tutoring
2. Teacher-support questions
3. Exercise generation and solution verification
4. Direct topic teaching

## Goals

- Classify user prompts into the correct workflow.
- Consider chat history.
- Consider attached files.
- Consider user settings.
- Use workflow-specific prompt templates.
- Persist chat messages.
- Keep workflow behavior modular for future expansion.

## Non-goals

- Public sign-up.
- Full admin content management UI.
- SSO.
- Multiple simultaneous class memberships per user.

## Main flow

1. User submits prompt.
2. Frontend sends prompt, chat ID, and attachment references.
3. Backend authenticates user.
4. Backend loads chat history.
5. Backend loads user settings.
6. Backend loads user training/class ID.
7. Workflow router classifies the prompt.
8. RAG retrieves class-scoped context.
9. Prompt builder creates workflow-specific prompt.
10. Chat LLM generates response.
11. Backend persists user message, assistant response, and useful metadata.
12. Frontend renders response.

## Workflow routing input

The router should receive:

- Current user prompt
- Recent chat history
- User settings
- Attachment metadata
- Training/class ID
- Available workflow definitions

## Workflow routing output

The router should return:

- Selected workflow
- Confidence if available
- Reasoning summary for debugging, not shown to user by default
- Whether RAG is needed
- Whether attachments are needed
- Any missing information

## Workflow-specific behavior

### Socratic tutoring

The assistant should guide the learner with questions and hints.

It should avoid giving a complete answer immediately unless the learner is stuck, asks for a final explanation, or the teaching settings allow it.

### Teacher-support questions

The assistant should help teachers generate useful questions.

Questions may target:

- Understanding
- Reflection
- Diagnosis
- Discussion
- Exam preparation
- Misconceptions

### Exercise generation and solution verification

The assistant may:

- Generate new exercises
- Generate solutions
- Check user-submitted solutions
- Explain mistakes
- Verify exercises that were not generated by spark-tutor

### Topic teaching

The assistant should directly explain a topic using:

- Structured explanation
- Examples
- Course-specific context
- Follow-up checks for understanding

## RAG requirements

Retrieval must always be filtered by the authenticated user’s training/class ID.

## Attachment requirements

Attachments may be used for:

- Exercise verification
- Reading submitted solutions
- Extracting external exercise text
- Contextualizing the user prompt

Attachments must be validated and parsed before use.

## Persistence requirements

Persist:

- User message
- Assistant response
- Chat ID
- User ID
- Workflow type
- Attachment references
- Timestamps
- Optional retrieval metadata for debugging

## Tests

### Unit tests

- Router selects Socratic tutoring for learning-guidance prompts.
- Router selects teacher-support questions for teacher question-generation prompts.
- Router selects exercise workflow for exercise generation.
- Router selects exercise workflow for solution verification.
- Router selects topic teaching for direct explanation requests.

### Integration tests

- User prompt creates persisted messages.
- Chat history affects workflow routing.
- User settings affect prompt behavior.
- Attached file can be used for solution verification.

### Security tests

- User cannot access another user’s chat.
- User cannot retrieve another class’s RAG content.
